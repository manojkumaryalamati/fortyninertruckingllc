You are a senior staff-level system design architect and full-stack engineer. Build a production-grade, modern trucking company web app for “FortyNinerTrucking LLC” with a public marketing website + a secure admin portal. The app must be responsive and work perfectly on mobile, tablet, and desktop.

TECH STACK (required)
- Frontend: Next.js 14+ (App Router) + TypeScript
- UI: TailwindCSS + shadcn/ui components (or equivalent modern component kit)
- Backend: Firebase (Authentication + Firestore + Storage)
- AuthN/AuthZ: Firebase Auth + custom claims (roles: SUPER_ADMIN, ADMIN, DISPATCHER, DRIVER_READONLY)
- Hosting: Firebase Hosting (or Vercel), but code must be compatible with Firebase
- Forms: react-hook-form + zod validation
- Data fetching/state: server actions + client hooks; use Firestore SDK with clean repositories
- Code quality: ESLint + Prettier + strict TS, modular architecture

CORE REQUIREMENTS
1) Public Website (Marketing)
- Pages: Home, Services, Fleet, Certifications, Permits/Compliance, Careers, Subhauler, Contact
- Modern hero section with CTA (“Request a Quote”, “Call Dispatch”)
- Fleet gallery with filters and image lightbox
- Certifications and permits shown as badges/cards and downloadable docs
- Careers page with driver application form (store submissions in Firestore)
- Contact page with form (store leads in Firestore) + map section placeholder
- SEO: metadata, OpenGraph, sitemap, robots, structured data (LocalBusiness)
- Performance: optimize images, lazy load galleries

2) Admin Portal (Secure)
- /admin protected routes with role-based access
- Admin features:
  a) Drivers Management (CRUD)
     - Add/Edit driver profile (name, phone, license number, status, assigned truck, notes)
     - Upload driver documents (CDL, medical card, insurance) to Firebase Storage, store metadata in Firestore
  b) Trucks Management (CRUD)
     - Truck details: truckNumber, VIN, plate, type (10-wheeler, super dump, end dump, transfer), capacity, status, maintenanceDueDate
     - Upload truck documents (registration, insurance)
  c) Trips Management (CRUD)
     - Trip details: tripId, date, dispatcher, driverId, truckId, pickupLocation, dropoffLocation, material, weight, rate, status (scheduled/in-progress/completed/cancelled)
     - Attach trip documents (BOL, tickets)
  d) Documents Center
     - Central list/search of all docs with filters by entity (driver/truck/trip), expiry dates, and download links
  e) Dashboard
     - KPIs: active drivers, active trucks, trips today, completed this month, docs expiring soon
     - Recent activity log (create/update/delete)

3) Authentication & Authorization (Firebase)
- Implement sign-in (email/password) and optional Google sign-in for admins
- First user becomes SUPER_ADMIN (or provide a secure seed admin via env var)
- Use Firebase custom claims for roles, verified on server side
- Enforce Firestore security rules to restrict access by role:
  - Public collections readable without auth only for marketing content if needed
  - Admin-only collections restricted by roles
- Provide clear “Access Denied” page and role-aware navigation

DATA MODEL (Firestore collections)
- users: { uid, email, name, role, createdAt }
- drivers: { id, name, phone, licenseNumber, status, assignedTruckId, createdAt, updatedAt }
- trucks: { id, truckNumber, vin, plate, type, capacity, status, maintenanceDueDate, createdAt, updatedAt }
- trips: { id, date, dispatcherUid, driverId, truckId, pickup, dropoff, material, weight, rate, status, notes, createdAt, updatedAt }
- documents: { id, entityType: "driver"|"truck"|"trip", entityId, docType, fileName, fileUrl, storagePath, expiryDate, uploadedBy, createdAt }
- leads: { id, name, email, phone, message, createdAt }
- applications: { id, name, email, phone, experienceYears, licenseType, message, createdAt }
- auditLogs: { id, actorUid, action, entityType, entityId, timestamp, diffSummary }
